network-skill-lab · spec

Phase 1 核心引擎

類型 正式開發（三層模型） 版本 v1 草案 日期 2026-09-23 撰寫 Fable 5.1（planner） 狀態 待批准

從瀏覽器完整跑完一題 guided 模式：選 lab、沙箱建起來、在兩個節點的 terminal 裡修好問題、checkpoint 即時打勾、自動結束、看到總時間與指令數。這一個 phase 把 DESIGN.md §2 的每個元件都做出最小可用版本，之後的 phase 只往上疊。

01目標與完成定義

完成定義（全部成立才算完成）：

  1. make build 產出單一 binary nsl，內含前端；nsl serve 啟動後開瀏覽器即可使用，不需登入。
  2. Lab 列表顯示 fixture lab net-ip-01-link-down，點「開始（guided）」後 15 秒內看到兩個節點的 terminal。
  3. 在 terminal 裡修好問題後，checkpoint 在 5 秒內打勾；全部通過後自動停錶並跳到結果頁，顯示總時間、指令數、每個 checkpoint 的通過時間，沙箱被銷毀。
  4. 放棄、關瀏覽器 15 分鐘、伺服器重啟，三種情況沙箱都會被回收，不留孤兒容器與網路。
  5. CI 綠燈：Go 與 TypeScript 的 lint、單元測試；Docker 整合測試在本機 make test-integration 通過。
  6. 指令歷史與 pty 錄影都落到磁碟並寫入資料庫（回放 UI 是 Phase 3）。

03待批的提案

批准這份 spec 即視為採納，有異議請指出編號。

P1 CI：GitHub Actions，每個 PR 跑 lint 與單元測試；Docker 整合測試只在本機 go vet、golangci-lint、go test ./...、eslint、tsc --noEmit、vitest。需要 Docker 的測試打 build tag integration，make test-integration 在本機跑。
理由：GitHub 的免費 runner 沒有 privileged 容器與 systemd。
P2 main 分支保護：必須走 PR、CI 綠燈、squash merge 你一個人時自己 approve。我會用 gh api 設定，需要你同意。
理由：前兩個 PR 是 merge commit 進去的，之後團隊加入前先把規則固定。
P3 License：MIT repo 是公開的，沒有 license 等於別人不能合法使用或貢獻。
理由：你要給團隊與面試者用，MIT 最不礙事。若你打算轉私有或另有考量，這條改掉即可。
P4 SQLite 用 modernc.org/sqlite（純 Go，無 cgo）
理由：交叉編譯與 CI 都不用裝 gcc；效能對單人使用綽綽有餘。
P5 前端以 go:embed 打包進 binary；開發時 Vite dev server 反向代理到 Go
理由：符合 D3 all-in-one；部署只有一個檔案。
P6 Phase 1 不做登入：資料庫預建一個 local 使用者，所有 attempt 掛在它名下
理由：D6 的帳號功能排在 Phase 3；資料模型從現在就有 user_id，之後只加登入不改 schema。
P7 Terminal 以 nsl 使用者登入（sudo NOPASSWD），不是 root
理由：貼近真實伺服器操作；題目需要 root 時使用者自己 sudo，這本身就是練習的一部分。setup / checks 腳本仍以 root 執行。
P8 Guided 模式的結束條件：某一次 checker 掃描中所有 checkpoint 同時通過 每個 checkpoint 記 first_passed_at 與最近狀態；UI 顯示最近狀態（修好又弄壞會變回未通過）。
理由：避免使用者先修 A 再弄壞 A 去修 B，最後系統卻判定通過。
P9 Docker 資源以 label 標記，啟動時清孤兒 所有容器與網路帶 nsl.attempt=<id> 與 nsl.managed=true；nsl serve 啟動時把資料庫裡非終態的 attempt 標為 expired，並刪掉所有帶 label 的 Docker 資源。
理由：伺服器重啟後不可能恢復 pty 連線，直接回收最乾淨。

05內容格式：Phase 1 子集

載入器只接受下列欄位，其他欄位一律報錯（之後的 phase 再放寬），避免內容偷偷依賴未實作的功能。

# lab.yaml
id: net-ip-01-link-down
version: 1
title: { zh: "伺服器連不到對外", en: "Server lost connectivity" }
topic: net/ip
level: 2
modes: [guided]
environment: container
estimated_minutes: 10
ticket:
  zh: "使用者反映 {{node_a}} 無法連到 {{node_b}}（{{ip_b}}）。請找出原因並修復。"
  en: "Users report {{node_a}} cannot reach {{node_b}} ({{ip_b}}). Find the cause and fix it."
params:
  node_a: { gen: const, value: web01 }
  node_b: { gen: const, value: db01 }
  subnet: { gen: const, value: 10.0.5.0/24 }
  ip_a:   { gen: const, value: 10.0.5.10 }
  ip_b:   { gen: const, value: 10.0.5.20 }
  iface:  { gen: const, value: eth1 }
setup: setup.sh
checkpoints:
  - id: link-up
    title: { zh: "{{iface}} 已 UP", en: "{{iface}} is up" }
    node: web01
    script: checks/01-link-up.sh
    visible: true
  - id: ping-peer
    title: { zh: "web01 可 ping 到 db01", en: "web01 can ping db01" }
    node: web01
    script: checks/02-ping-peer.sh
    visible: true
solution: { zh: solution.zh.md, en: solution.en.md }

# topology.yaml
nodes:
  web01: { role: ubuntu }
  db01:  { role: ubuntu }
links:
  - endpoints: ["web01:eth1", "db01:eth1"]
    subnet: "{{subnet}}"
    addresses: { web01: "{{ip_a}}/24", db01: "{{ip_b}}/24" }

驗證規則：id 與目錄名一致；modes 只能是 guided；params 只允許 const；{{}} 只能引用已定義的 param；checkpoint 的 node 必須存在於 topology；script 檔案必須存在且可執行；links 的 endpoints 介面不能是 eth0；每個 node 在同一 link 只能出現一次。違反任一條，nsl serve 拒絕啟動並列出所有錯誤。

腳本契約（同 DESIGN.md §3.5）：以 root 在指定 node 執行，param 以 NSL_<UPPER> 注入；setup 失敗 exit 非 0 則 attempt 進 error；checks 10 秒逾時視為失敗。

06Docker provider

實作 runner.Runner，全部行為由 Phase 0 實證（docs/PHASE0-RESULTS.md）。

Provision(spec)

  1. 建 nsl-<attempt>-mgmt（一般 bridge）與每條 link 一個 nsl-<attempt>-<n>（--internal，指定 subnet）。
  2. 每個 node：docker create，image nsl/node，--privileged --cgroupns=private，tmpfs /run、/run/lock、/tmp，hostname = node 名，只接 mgmt；role 為 k3s 時再掛 volume /var/lib/rancher/k3s/agent/containerd。
  3. 啟動後依 topology 的 links 順序 network connect --ip，保證 eth1、eth2 順序。
  4. 輪詢 systemctl is-system-running 到 running / degraded（上限 30 秒）。
  5. exec nsl-bootstrap，環境變數 NSL_NODE、NSL_ROLE、NSL_IFACES（k3s 再加 token / server）。各 node 平行。
  6. exec setup.sh（以 root，注入 params）。失敗則整個 sandbox 銷毀並回傳錯誤訊息（含 stderr 最後 20 行）。

OpenTerminal(sb, node)

docker exec -it -u nsl -w /home/nsl 執行 bash -l，環境 TERM=xterm-256color。回傳可讀寫的 PTY 與 resize 方法。每個 tab 一個 exec，關 tab 就結束該 exec。

Exec(sb, node, cmd, env, timeout)

無 TTY、以 root 執行，回傳 stdout、stderr、exit code。checker 與 recorder 都用它。

Destroy(sb)

rm -fv 所有容器、network rm 所有網路。冪等：資源不存在不算錯。

GC()

列出所有帶 nsl.managed=true 的容器與網路並刪除。nsl serve 啟動時呼叫一次。

Health()

Docker daemon 可連、nsl/node image 存在、可用記憶體。UI 在 lab 列表頁顯示。

07Attempt 生命週期

provisioning ──成功──▶ running ──全部 checkpoint 通過──▶ passed
     │                    │
     └─失敗──▶ error      ├─使用者放棄──▶ abandoned
                          └─heartbeat 斷 15 分鐘 / 伺服器重啟──▶ expired
  • 同一 user 同時只能有一個非終態 attempt；再建回 409。
  • elapsed_ms 只累計 running 期間，由伺服器計算；UI 的計時器以伺服器時間校正，不自己數。
  • heartbeat：events WebSocket 連線存在即視為在線；所有連線斷開超過 15 分鐘 → expired。設定 NSL_IDLE_TIMEOUT 可改。
  • 進入任何終態都呼叫 Destroy，並在 UI 顯示結果頁。error 狀態的結果頁顯示失敗原因與「重試」。
  • Attempt 的事件（狀態變更、checkpoint 變更、計時同步每 10 秒）透過 attempt.Bus 廣播到 events WebSocket。

08Checker

  • attempt 進 running 後啟動一個 goroutine，每 NSL_CHECK_INTERVAL（預設 5 秒）跑一輪：所有 checkpoint 平行 exec，逾時 10 秒。
  • 每輪結果寫 checkpoint_runs（last_status、last_run_at；首次通過寫 first_passed_at），有變化才廣播事件。
  • 同一輪全部通過 → 呼叫 attempt 的 Finish(passed)（P8）。
  • Checker 執行期間若 attempt 已終態，立即停止。

09Recorder

  • 指令歷史：每 5 秒對每個 node exec tail -c +<offset> /var/log/nsl/commands.jsonl，逐行解析寫入 command_log，記住 offset。無法解析的行丟棄並計數。
  • pty 錄影：每個 terminal tab 一個 asciicast v2 檔（<data>/recordings/<attempt>/<node>-<tab>.cast），header 含 width / height / timestamp，輸出事件 "o"、輸入事件 "i"、resize 事件 "r"。寫入走 buffered writer，關 tab 或 attempt 終態時 flush。
  • recordings 表記路徑與起訖時間。
  • 結果頁的「指令數」= command_log 中該 attempt 的筆數。

10API

REST 皆為 JSON，錯誤格式 {"error":{"code":"...","message":"..."}}。所有 {id} 是 attempt id（ULID）。

方法與路徑用途回應重點
GET /api/healthRunner 健康docker、image、記憶體
GET /api/labsLab 列表id、title、topic、level、modes、estimated_minutes
GET /api/labs/{lab_id}單一 lab加 nodes（名稱、role）、visible checkpoints 的 title
POST /api/attempts開始練習 {lab_id, mode}201 attempt；409 已有進行中
GET /api/attempts/current目前非終態 attempt204 沒有
GET /api/attempts/{id}attempt 詳情status、lab、ticket（已套 params）、nodes、checkpoints 狀態、elapsed_ms、server_time
POST /api/attempts/{id}/abandon放棄200 結果
GET /api/attempts/{id}/result結果頁資料elapsed_ms、command_count、checkpoints（first_passed_at）、solution（雙語 markdown）
WS /ws/attempts/{id}/events事件流JSON 訊息：status、checkpoint、tick、error；連線本身即 heartbeat
WS /ws/attempts/{id}/term/{node}/{tab}Terminalbinary frame = pty 位元組雙向；text frame = JSON 控制 {"type":"resize","cols":..,"rows":..}

WebSocket 的寫入有 buffer 上限（每連線 1 MB），超過則關閉連線並記 log，避免慢客戶端拖垮伺服器。

11Web UI

頁面內容
/ Lab 列表卡片：title、topic、level、預估時間、「開始」按鈕（只有 guided）。頂部：Runner 健康、語言切換。若有進行中 attempt，顯示「繼續」並禁止開新的。
/attempts/{id} 練習頁三欄：左「工單」面板（ticket、checkpoint 清單即時打勾、放棄按鈕）；中 terminal workspace（dockview，每個 node 預設一個 tab，可加 tab、可左右分割）；底部狀態列（計時器、attempt 狀態、各節點狀態）。provisioning 期間顯示進度文字（建網路 → 起節點 → bootstrap → setup）。
/attempts/{id}/result 結果頁總時間、指令數、checkpoint 表（通過時間）、解答（markdown）、「回列表」。
  • xterm.js：addon-fit 隨容器大小 resize 並送 resize 控制訊息；斷線顯示提示並自動重連（指數退避，上限 30 秒）。
  • i18n：i18next，UI 字串 zh-TW 與 en 兩份 JSON，語言存 localStorage；內容的 title / ticket 由 API 依 Accept-Language 或 query ?lang= 回傳對應語言。
  • 狀態管理 zustand；資料以 REST 初載、events WS 更新。
  • 不做的：主題切換、鍵盤快捷鍵、行動版排版（可用即可）。

12資料模型

照 DESIGN.md §5 建表，migration 用嵌入的 SQL 檔依序執行（schema_migrations 記版本）。Phase 1 差異：

  • users 預建一筆 local（role user，無密碼）。
  • attempts.status 的 enum：provisioning | running | passed | abandoned | expired | error（submitted 留 Phase 2）；加 error_message 欄位。
  • id 一律 ULID 字串。時間欄位存 UTC RFC 3339。

15風險

  • WebSocket 與 pty 的邊界情況（貼上大量文字、快速 resize、瀏覽器分頁休眠）。T7 的 backpressure 與 T9 的重連是對策；不追求完美，能不當機即可。
  • dockview 的學習成本。若 T9 在半天內做不出分割與 tab，退回單純的 tab 列（不分割），分割留 Phase 3。
  • docker/docker client 版本。Docker Engine 29 的 API 版本較新，client 固定用 negotiate。
  • Opus 的 task 若跨模組會膨脹。T4、T7 最大，必要時再各拆兩半。
