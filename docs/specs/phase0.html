03待批的提案

以下八項於 2026-09-21 隨 spec 一併採納。

P1 腳本形式：純 bash，make 驅動 每支一個腳本加共用 lib.sh，make -C spikes/phase0 s2 跑單支，all 跑全部。每支印 PASS / FAIL，量測數字寫進 spikes/phase0/results/<id>.txt。
理由：驗的是 Docker 與 systemd 的行為，不是 Go；bash 最短路徑。
P2 Image 一次建完整版，含 k3s 離線 image S1 直接建 DESIGN.md §4 的 66 套件版，並把 k3s airgap tarball（約 250 MB）ctr images import 進去。
理由：Dockerfile 就是正式產物，不重工；S3 要驗「不拉網路也能起叢集」，非塞不可。
P3 resolv.conf 交給 systemd-resolved：bootstrap 先 umount Docker 會把 /etc/resolv.conf、/etc/hosts、/etc/hostname 以 bind mount 蓋進容器。bootstrap 在 privileged 容器內 umount 這三個檔，再讓 resolved 接管成 symlink。列入 S2 的 R2 驗證項。
理由：所有 DNS 題都依賴 resolvectl 行為與真實伺服器一致；不 umount 就永遠是 Docker 的 127.0.0.11。
P4 介面順序：建容器只接管理網路，再依 topology 順序逐一 connect Docker 多網路同時接上時，eth1、eth2 是按網路名稱排序，不是宣告順序。改為 docker create --network mgmt 後依序 docker network connect，順序即宣告順序。S2 驗證。
理由：比 MAC 對照改名簡單，且不需要 udev 規則。
P5 冷啟動定義與門檻 從 docker run 第一個節點起，到 bootstrap 完成且 setup 可執行為止；image 已在本機。門檻：純 Ubuntu 雙節點 < 10 秒；k3s server + agent 雙節點到兩節點 Ready < 30 秒。
理由：R5 原文只寫「< 30 秒（含 k3s）」，沒定起訖點，量出來的數字會沒法比較。
P6 方案 A 的失敗判準 見 §06。符合任一項即退方案 B，並在本 phase 內補做 B 的最小驗證。
理由：沒有判準會變成「再試一下」的無底洞。
P7 資源上限：先量再說 S3 量每個 k3s 節點的 RSS 與閒置 CPU，寫入結果文件；是否調高 .wslconfig 由數字決定。
理由：這個數字直接決定 L5 複合題最多幾個節點，猜沒有意義。
P8 加 S0 環境檢查 S1 之前先確認 WSL 核心有 vxlan、nf_tables、nf_conntrack、bridge、8021q、dummy、veth 模組，cgroup v2 unified，Docker 版本，/dev/kmsg 可用。
理由：k3s 的 flannel 靠 vxlan、題目靠 nft；缺任一個 S3 / S2 直接白跑。

05Bootstrap 契約草案

S2 會產出一支 bootstrap.sh，之後 Phase 1 的 Docker provider 用同一份邏輯。它在容器內以 root 執行，輸入是環境變數：

變數意義
NSL_NODE節點名稱，設為 hostname
NSL_ROLEubuntu / ubuntu-nm / k3s-server / k3s-agent
NSL_IFACES依序的介面與位址，例如 eth1=10.0.5.10/24,eth2=192.168.1.1/24
NSL_K3S_SERVERagent 用：server 的 URL 與 token

bootstrap 做的事：umount Docker 的三個檔、依 role 選 networkd 或 NetworkManager、寫 netplan、netplan apply、依 role 起 k3s。這份契約在 Phase 0 結束時定稿，寫進 DESIGN.md。

06方案 A 失敗判準與退路

符合任一項即判定方案 A 失敗：

  1. netplan apply 後 networkd 無法在 eth1 宣告位址，或位址與 Docker 配的衝突導致介面不穩。
  2. docker network connect / disconnect 或 docker restart 後，Docker 把位址改回自己配的值。
  3. 穩定觀察 10 分鐘內，位址、路由或介面狀態有非預期變動。
  4. resolv.conf 無法交給 resolved（umount 失敗或重啟後被蓋回）。

退路 B。容器以 --network none 建立，只由 runner 在 host 端建 veth pair，一端 ip link set netns 進容器，另一端接 host bridge。位址完全由容器內 netplan 設定，Docker 不參與。這是 containerlab 的做法。

若退 B，在本 phase 內補一支 S2b 驗最小可行（兩節點互 ping、restart 後 veth 仍在），詳細設計留 Phase 1 spec。

08風險與依賴

  • WSL2 核心。若 S0 缺 vxlan 或 nf_tables，需要自編 WSL 核心或改用 host-gw，這會是第一個回報點。
  • Image 建置需要網路。66 套件加 k3s 約需下載 1 GB 以上，第一次建置可能 10 到 20 分鐘。
  • WSL 記憶體。S3 同時跑兩個 k3s 節點可能逼近 5.8 GB，若 OOM 會直接建議調 .wslconfig。
  • Docker 29 的 systemd 相容性。privileged 加 cgroup v2 一般沒問題，但 Docker 29 較新，S1 若卡住會先試 --cgroupns=host。
