Phase 3 帳號與歷史

類型 正式開發（三層模型） 版本 v1 草案 日期 2026-09-24 撰寫 Fable 5.1（planner） 狀態 待批准

Phase 2 之後系統只有一個匿名使用者。Phase 3 讓多個人各自登入、各自練習、各自回看：本地帳密、admin 與 user 兩種角色、歷史紀錄頁、指令歷史與 pty 錄影回放。同時把 Phase 2 驗收留下的穩健性問題（啟動 GC、systemd 等待、k3s 路由）一次收掉，因為多人同時使用時這些會從偶發變常態。

01目標與完成定義

  1. 多人各自練習。兩個帳號同時登入（兩個瀏覽器），各自開一題，兩個沙箱並存互不干擾，彼此看不到對方的 attempt、歷史與進度。
  2. 未登入一律拒絕。所有 /api 與 /ws 對未登入回 401；登入後 session 7 天滑動有效；登出即失效。
  3. admin 管帳號。admin 頁能建立使用者、重設密碼、停用、改角色；被停用者立刻登不進來，現有 session 也失效。
  4. 歷史可回看。歷史頁列出自己的每個 attempt（lab、模式、狀態、時間、提交次數）；詳情頁有結果、指令歷史（時間、節點、指令、exit code）、每個 terminal 分頁的錄影，可播放、暫停、拖曳。
  5. admin 看得到所有人。admin 的歷史頁可切換使用者，看任何人的詳情與回放。
  6. 併發有上限。同時沙箱數達到 NSL_MAX_SANDBOXES 時，第 N+1 個開題得到明確訊息（誰在用、幾個），不會排隊也不會掛住。
  7. 穩健性。#56、#57 修好：伺服器啟動時 GC 只清自己的資源且不致命；systemd 等待放寬並回報狀態。Phase 1、2 的驗收條目與 make test-content 全部維持通過。

03待批的提案

批准這份 spec 即視為採納，有異議請指出編號。

P1 密碼 argon2id，session 存 DB、HttpOnly + SameSite=Lax cookie、7 天滑動 參數 time=1、memory=64 MB、threads=4（golang.org/x/crypto/argon2）。session id 32 bytes 隨機，cookie 名 nsl_session；每次請求更新 last_seen_at，超過 7 天未用即失效；登出刪 row。無 remember-me、無 CSRF token（SameSite=Lax + 只用 JSON body 的 POST 已足夠，並拒絕非 JSON content-type 的寫入請求）。
理由：D6 要簡單；DB session 讓「停用即失效」與「登出所有裝置」不用額外機制。
P2 首個 admin 由 CLI 建立：nsl user add <name> --role admin（互動輸入密碼或 --password-stdin） nsl serve 在使用者數為 0 時照常啟動但登入頁顯示「尚未建立帳號，請在伺服器執行 nsl user add」。不用環境變數塞密碼。
理由：密碼不進 env 與 log；CLI 與 serve 共用 store，最少程式碼。
P3 既有的 local 使用者在 migration 0003 標為停用，資料保留 它的 attempt、進度、錄影仍在，admin 的歷史頁可看到（顯示為 local）。
理由：不刪資料；沒有人需要以 local 登入。
P4 併發上限以「沙箱數」計，NSL_MAX_SANDBOXES 預設 3；超過回 429 runner_busy，不排隊 回應含目前使用中的沙箱數與上限；UI 顯示「目前 3 個沙箱使用中，請稍後再試」。admin 不豁免。
理由：5.8 GB 主機跑 3 個沙箱（含一個 k3s 雙節點）約 2.5 GB，是安全線；排隊會引出等待時間與逾時語意，留給 Phase 4。
P5 回放用 asciinema-player npm 套件打包進前端，錄影檔經認證端點以 JSON 串流 播放器讀 GET /api/attempts/{id}/recordings/{rid}/cast（asciicast v2 原文），支援播放、暫停、進度拖曳、速度 1x/2x/4x；idle time limit 2 秒（長時間沒輸出自動跳過）。
理由：D14 只要求錄影先落地，回放 UI 現在做；官方播放器最省事，套件約 300 kB，接受。
P6 admin 可看所有人的歷史與回放，但不能看進行中的 terminal 歷史頁的使用者切換只給 admin；進行中的 attempt 在列表顯示狀態但詳情頁只在終態後可開。
理由：即時觀看是面試功能（Phase 5），牽涉 pty 分流；Phase 3 只做「事後」。
P7 進行中 attempt 的所有權：只有本人能連 events / terminal、放棄、提交；admin 只能「強制放棄」 新增 POST /api/admin/attempts/{id}/abandon，用於清掉卡住的沙箱。
理由：多人共用主機時，admin 需要回收工具，但不該進別人的 terminal。
P8 GC 依 instance 標籤限定（#57）：每個 nsl 行程用 nsl.instance=<NSL_INSTANCE 或資料目錄路徑的 hash>，只清自己的；測試套件用隨機 instance 啟動 GC 先刪容器再刪網路，網路「仍有 endpoint」錯誤重試 5 次後只記 log 不退出。
理由：Phase 2 驗收時驗收伺服器與整合測試互相清掉對方的沙箱，也讓 serve 直接退出。
P9 systemd 等待上限 60 秒（#56），失敗訊息帶最後狀態與 systemctl list-jobs；provisioning 事件不變
理由：多人同時開題時主機負載會高，30 秒太緊；60 秒仍在 UI 可接受範圍。
P10 錄影與指令歷史的保留：Phase 3 不自動清理，admin 頁顯示磁碟用量與每個 attempt 的錄影大小，可手動刪除 attempt（含檔案）
理由：配額與策略需要真實使用數據，先給工具。

04架構變更

internal/
  auth/         密碼雜湊、session 建立與驗證、中介層（從 cookie 取 user，注入 context）
  store/        + sessions 表；users 加 disabled_at；migration 0003；CommandLog / Recordings 查詢端點用的方法
  api/          + /api/auth/*、/api/admin/*、/api/history/*、recordings 串流；所有既有端點改用 context 內的 user；併發上限
  attempt/      + 依 user 的所有權檢查；沙箱計數；admin 強制放棄
  provider/docker/  + instance 標籤、GC 重試、systemd 60 s
cmd/nsl/        + `user add | passwd | disable | list`
web/            + 登入頁、AuthGate、頁首、admin 頁、歷史列表與詳情、播放器

依賴方向不變；auth 只依賴 store。前端所有頁面包在 AuthGate 內，未登入導向 /login。

05帳號與 session

  • 使用者名稱：3 到 32 字元，[a-z0-9_-]，唯一；密碼至少 8 字元，不做其他規則。
  • 角色 admin | user；admin 不能停用或降級自己（避免鎖死）。
  • 登入失敗回 401 invalid_credentials，不區分帳號不存在與密碼錯；同一 IP 連續失敗 10 次後 60 秒內回 429 too_many_attempts（記憶體內計數即可）。
  • CLI：nsl user add <name> [--role admin|user]（密碼從 tty 或 --password-stdin）、nsl user passwd <name>、nsl user disable|enable <name>、nsl user list。CLI 直接開 store（伺服器可同時在跑，SQLite WAL 允許）。
  • locale：使用者的 locale 欄位在登入時作為 UI 預設語言，前端切換時回寫（PATCH /api/auth/me）。

06API

所有既有端點加上認證；local 使用者的硬編碼全部改為 context 內的 user。錯誤格式不變。

POST /api/auth/login   { "username", "password" }      → 200 Me | 401 invalid_credentials | 429 too_many_attempts | 403 user_disabled
POST /api/auth/logout                                    → 204
GET  /api/auth/me                                        → 200 Me | 401
PATCH /api/auth/me     { "locale": "zh"|"en" }           → 200 Me
Me = { "id", "username", "role", "locale", "created_at" }

GET  /api/admin/users                                    → [ User ]   User = Me + { "disabled_at": null|time, "attempts": n }
POST /api/admin/users  { "username", "password", "role" } → 201 User | 409 username_taken
PATCH /api/admin/users/{id} { "role"? , "disabled"? bool, "password"? } → 200 User | 400 cannot_modify_self
POST /api/admin/attempts/{id}/abandon                    → 200 Attempt
DELETE /api/admin/attempts/{id}                          → 204（終態才可；刪 DB 列與錄影檔）
GET  /api/admin/stats                                    → { "sandboxes_active", "sandboxes_max", "recordings_bytes", "attempts": n }

GET  /api/history?user_id=&limit=&before=            → [ HistoryItem ]（user_id 只有 admin 可指定；預設自己；依 created_at 倒序，游標分頁）
HistoryItem = { "id", "lab": LabSummary, "mode", "status", "elapsed_ms", "submit_count", "command_count",
                "created_at", "ended_at", "user": { "id", "username" } }
GET  /api/attempts/{id}/commands?limit=500&after=       → [{ "id", "node", "ts", "user", "cwd", "command", "exit_code" }]
GET  /api/attempts/{id}/recordings                       → [{ "id", "node", "tab", "started_at", "ended_at", "bytes" }]
GET  /api/attempts/{id}/recordings/{rid}/cast            → text/plain asciicast v2 原文（Content-Length，支援 Range 不必要）

POST /api/attempts                                       → 429 runner_busy { "error": { ..., "message" }, "sandboxes_active", "sandboxes_max" }
所有 /api/attempts/{id}* 與 /ws/attempts/{id}*：非本人 → 404 not_found（不洩漏存在性）；admin 對終態 attempt 的 GET 類端點放行。

07Web

頁面內容
/login帳號密碼表單、錯誤訊息、語言切換；成功後回到原本要去的路徑
頁首使用者名稱、角色徽章、登出；admin 多一個「管理」連結
/admin使用者表（名稱、角色、建立日、attempt 數、停用狀態）、建立使用者表單、每列的重設密碼 / 停用 / 改角色；統計列（沙箱使用 n/m、錄影總大小）；進行中 attempt 清單與「強制放棄」
/history自己的 attempt 列表（lab、模式、狀態徽章、時間、耗時、提交次數），無限捲動；admin 有使用者下拉
/history/{id}三個分頁：結果（沿用結果頁元件）、指令（表格，可依節點篩選）、錄影（每個分頁一個播放器，asciinema-player）；admin 多「刪除」
Lab 列表與詳情開題遇到 429 顯示沙箱使用量與提示
  • AuthGate：app 啟動先打 /api/auth/me；401 導向登入；任何 API 回 401 時清 session 狀態並導向登入。
  • WS 的 401 在 upgrade 前回 JSON；前端把 events socket 的 401 關閉碼視為登出。
  • i18n 全部雙語；locale 與帳號同步。

09資料模型

  • migration 0003：users 加 disabled_at TEXT、updated_at；sessions(id TEXT PK, user_id FK CASCADE, created_at, last_seen_at, expires_at, user_agent) 與 (user_id) 索引；UPDATE users SET disabled_at = now WHERE username = 'local'。
  • recordings 加 bytes INTEGER（Close 時寫入）。
  • attempts 不變；查詢加 ListByUser(userID, before, limit) 與 CountActiveSandboxes()（provisioning|running）。

11風險

  • 認證改動面大：所有端點與 WS 都要過中介層，測試 harness 要帶 session。T3 是最大 task，必要時拆成「中介層 + auth」與「history / admin」兩個 PR。
  • 兩個沙箱並存的資源：兩個 k3s 雙節點同時跑約 2.2 GB，加上主機其它負載可能觸發 #59 類的問題；T1 的 inotify 警告與 P4 的上限是防線。
  • asciinema-player 與 Vite：套件是 ESM，理論上直接可用；若 CSS 或 worker 打包有問題，退路是把播放器獨立成 lazy chunk。
  • 驗收需要兩個瀏覽器：API 層可用兩個 cookie jar 模擬；視覺確認再請你用無痕視窗開第二個帳號。
